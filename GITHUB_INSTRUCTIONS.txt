دليل تجهيز ونشر اليوسفي سوفت عبر GitHub Actions
================================================

هذه النسخة ليست مشروع Flutter؛ التطبيق React/Vite/Capacitor محلي أولاً.
ملف android/ هو مشروع Capacitor Android، وGitHub Actions يبني APK باستخدام
Gradle بعد مزامنة الأصول المحلية. لا يوجد خادم Express مطلوب لتشغيل التطبيق.

1) فك ضغط الحزمة
-----------------
1. نزّل الملف: yousifi-soft-github.zip.
2. فك الضغط على جهازك في مجلد جديد.
3. تأكد أن الملفات المخفية ظهرت أيضاً، وخاصة:
   - .github/workflows/android.yml
   - android/
   - artifacts/alyousifi-soft/
   - package.json و pnpm-lock.yaml
4. لا ترفع مجلد node_modules أو build. يقوم workflow ببناء dist ومزامنته عبر Capacitor.

2) إنشاء مستودع GitHub ورفع الملفات من المتصفح
------------------------------------------------
1. افتح https://github.com وسجّل الدخول.
2. اضغط + ثم New repository.
3. اختر اسماً للمستودع، مثل yousifi-soft، واجعله خاصاً أو عاماً حسب رغبتك.
4. لا تنشئ README أو .gitignore إضافياً إذا كانت الحزمة تحتوي هذه الملفات.
5. افتح المستودع الجديد واضغط Add file ثم Upload files.
6. من المجلد الذي فككت ضغطه، حدّد كل الملفات والمجلدات، بما فيها المجلد
   المخفي .github. إذا لم يظهر .github في مدير الملفات، فعّل إظهار الملفات
   المخفية أو ارفع ملف .github/workflows/android.yml من داخل صفحة GitHub.
7. اسحب الملفات إلى صفحة GitHub وانتظر اكتمال الرفع.
8. في أسفل الصفحة اختر Commit directly to the main branch ثم اضغط Commit changes.

مهم: ارفع محتويات المجلد بعد فك الضغط، وليس ملف yousifi-soft-github.zip نفسه
فقط. يجب أن يكون المسار في GitHub هو:
    .github/workflows/android.yml
وليس:
    yousifi-soft-github/.github/workflows/android.yml

3) تشغيل GitHub Actions
------------------------
1. افتح تبويب Actions داخل المستودع.
2. اختر Build Android APK من القائمة الجانبية.
3. عند الرفع إلى فرع main أو master سيبدأ البناء تلقائياً.
4. للتشغيل اليدوي، اضغط Run workflow، اختر الفرع main، ثم اضغط Run workflow.
5. انتظر حتى تصبح المهمة بعلامة نجاح خضراء. البناء يثبت Node.js وpnpm وJava 21
   وAndroid SDK، يبني نسخة الويب، ينفذ `npx cap sync android`، ثم يبني APK
بصيغة debug القابلة للتثبيت للاختبار الداخلي.

4) تنزيل app-debug.apk
-------------------------
1. افتح عملية البناء الناجحة من صفحة Actions.
2. انزل إلى قسم Artifacts في أسفل صفحة العملية.
3. اضغط على yousifi-soft-apk لتنزيل ملف ZIP الخاص بالـ artifact.
4. فك ضغط ملف الـ artifact الذي تم تنزيله.
5. ستجد داخله الملف:
       app-debug.apk
6. انقل APK إلى هاتف Android، اسمح بالتثبيت من هذا المصدر عند طلب النظام،
   ثم ثبّته. عند تثبيت تحديث فوق نسخة سابقة لا تحذف التطبيق القديم؛ اختر
   التحديث حتى تبقى بيانات المبيعات والعملاء والمخزون.

ملاحظة التوقيع: هذه الحزمة مهيأة للتوزيع اليدوي الداخلي باستخدام توقيع debug
حتى ينتج Actions ملف APK قابلاً للتثبيت مباشرة. قبل اعتماد التطبيق كتحديث
مستمر على أجهزة العملاء أو نشره في متجر، يجب إعداد keystore إصدار ثابت في
GitHub Secrets واستخدام المفتاح نفسه في كل بناء؛ اختلاف توقيع APK قد يمنع
Android من قبول التحديث. تغيير التوقيع ليس سبباً لحذف التطبيق أو مسح بياناته.

5) قاعدة الحفاظ على البيانات
----------------------------
- رقم التطبيق الثابت هو com.alyousifisoft.app. لا تغيّره في تحديث مستقبلي.
- الإصدار الحالي هو 1.0.15 ورقم البناء 16.
- بيانات التطبيق تحفظ محلياً في SQLite عبر Capacitor، مع localStorage وIndexedDB
  كـ fallback للويب، وتحديث APK لا يحذف
  مجلد بيانات التطبيق.
- لا تستخدم حذف التطبيق قبل تثبيت التحديث، ولا تضف في سير العمل أي خطوة
  deleteDatabase أو clear لبيانات WebView.
- إذا تغيّر شكل البيانات، ارفع SCHEMA_VERSION واكتب migration غير مدمرة.
- زر إعادة ضبط البيانات داخل التطبيق إجراء يدوي اختياري ويحذف السجلات فقط بعد
  تأكيد المستخدم؛ لا علاقة له بتحديث APK.

6) إذا فشل البناء
-----------------
1. افتح العملية الفاشلة من Actions.
2. افتح خطوة الفشل واقرأ أول رسالة Error، وليس التحذيرات العادية.
3. تأكد أن package.json وpnpm-lock.yaml وandroid/ وملف workflow موجودة في
   جذر المستودع.
4. أعد تشغيل workflow بعد تصحيح الملفات من خلال Run workflow.
